SR-ARCH1 [Non-Functional Requirement] SystemArchitecture: The SRanger system is a small ground robot that travels in a straight line and turns in place when it detects an obstacle. The robot carries a single infrared (IR) distance sensor mounted facing forward and a differential-drive motor pair that accepts a combined linear / angular velocity command. The controller is reactive: its only sensor input is the IR-driven obstacle event; a system-level endTask event is available to halt the controller. The controller issues motor commands as advisory events to the differential-drive layer.

SR-ARCH2 [Non-Functional Requirement] ControllerArchitecture: The SRanger controller is composed of: (1) a Sensor interface that exposes the latest IR distance reading, (2) an Actuator interface that records the last motor command, (3) a small set of state variables (notably a clock-reset timestamp for the timed Turning → Moving transition), and (4) a single state machine that selects transitions based on the input event, the IR distance, and the elapsed time in the current mode.

SR-DM1 [Non-Functional Requirement] SRangerMode: The SRanger controller has exactly three operating modes: Moving (initial mode — the robot drives forward at the configured linear velocity), Turning (the robot rotates in place at the configured angular velocity), and Final (a terminal mode entered when the operator issues endTask). At start-up the controller is in Moving.

SR-DM2 [Non-Functional Requirement] SRangerConstants: The SRanger controller defines four real-valued constants: moveVel (default 1.0, m/s — linear velocity command when Moving), turnVel (default 2.0, rad/s — angular velocity command when Turning), obstacleThreshold (default 0.5, metres — IR-distance threshold for the obstacle-detection condition), and turnDuration (default 2.0, seconds — how long the controller remains in Turning before returning to Moving). All four are fixed configuration constants for the controller.

SR-DM3 [Non-Functional Requirement] InputEvent: The SRanger controller receives input events from three sources. obstacle (signal, no payload) — emitted by the IR sensor framework when the distance reading crosses below obstacleThreshold. tick (signal, no payload) — delivered each control cycle by the system framework. endTask (signal, no payload) — emitted by the operator-level shutdown channel to terminate the controller into Final.

SR-DM4 [Non-Functional Requirement] OutputEvent: The SRanger controller emits a single output event, Move, carrying two real values — a linear velocity and an angular velocity — a combined command to the differential-drive layer. The same event covers forward motion (Move(moveVel, 0)), turning in place (Move(0, turnVel)), and stopping (Move(0, 0)); the controller introduces no other output events.

SR-DM5 [Non-Functional Requirement] SensorInterface: The Sensor exposes the latest IR distance reading: distance() returns a real number in metres, non-negative. When no reading is available (e.g., the sensor has not yet been initialised), distance() returns a large default value so that the obstacle-detection condition is not falsely triggered by missing data.

SR-DM6 [Non-Functional Requirement] Actuator: The Actuator receives Move(lv, av) events from the controller and stores the latest issued command. The Actuator exposes the last commanded linear and angular velocity for inspection. No other output channels exist.

SR-SF1 [Non-Functional Requirement] Distance: The Sensor provides a function distance() that returns the latest IR distance reading. The reading is in metres, non-negative, and is the only sensor measurement the SRanger controller consumes.

SR-Var1 [Functional Requirement] Variable_clockResetTime: The controller maintains a real variable clockResetTime (seconds) recording when the controller most recently entered the Turning state. It is set to the current time as an entry action on the Moving → Turning transition. The autonomous Turning → Moving transition fires when the elapsed time since clockResetTime is at or above turnDuration.

SR-FR1 [Functional Requirement] StateMoving: Moving is the initial mode on power-up. In Moving the robot drives forward: on entering Moving, the controller issues Move(moveVel, 0) to the actuator (linear velocity only, zero angular).

SR-FR2 [Functional Requirement] StateTurning: In Turning the robot rotates in place. On entering Turning the controller issues Move(0, turnVel) to the actuator (zero linear, angular only) and records the current time in clockResetTime.

SR-FR3 [Functional Requirement] StateFinal: Final is the terminal mode entered when the operator issues endTask. On entering Final the controller issues Move(0, 0) to the actuator (full stop).

SR-GP1 [Functional Requirement] GuardPredicate_obstacleDetected: The controller evaluates a condition obstacleDetected reflecting whether the IR sensor reads a distance at or below the obstacle-detection threshold (distance <= obstacleThreshold). The condition is used as the guard on the Moving → Turning transition.

SR-GP2 [Functional Requirement] GuardPredicate_turnDurationElapsed: The controller evaluates a condition turnDurationElapsed reflecting whether the elapsed time since clockResetTime is at or above the configured turn duration. The condition is used as the guard on the Turning → Moving transition.

SR-Beh1 [Functional Requirement] InitialState: On power-up, the SRanger controller begins in Moving.

SR-Beh2 [Functional Requirement] Moving_to_Turning: The SRanger controller transitions from Moving to Turning when the obstacle event is received. On this transition, set clockResetTime to the current time and issue Move(0, turnVel) as the entry action of Turning (per SR-FR2).

SR-Beh3 [Functional Requirement] Moving_to_Final: The SRanger controller transitions from Moving to Final when the endTask event is received. On this transition, issue Move(0, 0) as the entry action of Final (per SR-FR3).

SR-Beh4 [Functional Requirement] Moving_to_Moving_tick: The SRanger controller transitions from Moving to Moving (no mode change) when the tick event is received. The controller performs no action on this transition.

SR-Beh5 [Functional Requirement] Turning_to_Moving: The SRanger controller transitions from Turning to Moving when the turnDurationElapsed condition becomes true — i.e., when the time since clockResetTime is at or above turnDuration (autonomous, no event required). On this transition, issue Move(moveVel, 0) as the entry action of Moving (per SR-FR1).

SR-Beh6 [Functional Requirement] Turning_to_Final: The SRanger controller transitions from Turning to Final when the endTask event is received. On this transition, issue Move(0, 0) as the entry action of Final (per SR-FR3).

SR-Beh7 [Functional Requirement] Turning_to_Turning_tick: The SRanger controller transitions from Turning to Turning (no mode change) when the tick event is received. The controller performs no action on this transition.

SR-DC1 [Non-Functional Requirement] UniqueTransitions: Each behavioural requirement (SR-Beh1 through SR-Beh7) maps to exactly one transition in the state machine. There are no duplicate transitions for the same source mode and trigger event combination.
