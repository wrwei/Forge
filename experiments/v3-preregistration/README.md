# Pre-registration v3: cold passes and loop runs under study-free instructions

This folder holds the design of the collection reported in Sections 4.5, 4.6 and 4.9
of the paper, and everything used to run and audit it.

| File | What it is |
| ---- | ---------- |
| `prereg-v3-study-free.md` | the pre-registration, recorded on 29 October 2026 before any session, with its dated amendments. Each amendment was committed before the change it describes and before any session it affects. |
| `v3-operator-sheet.md` | the operator's procedure for each session |
| `v3-prompts/` | the exact prompt each session received, generated by `scripts/make_v3_prompts.py`; `superseded-*/` keeps the prompts of sessions that were later superseded |
| `scripts/` | the start, finish, setup and runner scripts, the leakage gate and its tests, the session recorder (`snapshot_v2.py`), the audit-log extractor, the rescoring scripts and the analysis scripts (`v3_analysis.py`, `v3_sb_requirement_split.py`) |

The sessions' records are in `experiments/v3-cold` and `experiments/v3-reference`, one
folder per session with its Java, pipeline reports, exported transcript and audit
(`TRANSCRIPT_AUDIT.md`). The analysis output is in `experiments/v3-analysis`. Sessions
replaced under an amendment are kept, with the reason, in `experiments/v3-superseded-a*`.
The regression records `experiments/regression-2026-*` show, for each pipeline change, which
recorded sources it affects.

The scripts were run on the authors' machine and contain its absolute paths.

In the published copies of `setup_v2_run.sh`, `run_claude_iteration.sh` and
`snapshot_v2.py`, the authors' internal issue numbers are replaced by neutral names
(`repairN`). The checks that read those names run only for earlier collections; for a
v3 session `setup_v2_run.sh` checks each repair by its code instead, so the scripts
behave as they did for every session recorded here.
