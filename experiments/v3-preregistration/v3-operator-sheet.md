# Pre-registration v3 — operator sheet

Pre-registration: `review/prereg-v3-study-free.md`. Prompts: `review/v3-prompts/`.
46 sessions in all (30 cold passes, 16 Reference runs), one fresh Claude Code
session each, never reused, one at a time.

## 0. Before the first session (once)

Push both repositories, so the pre-registration, the prompts and the instrument are
public before any data exists:

```bash
cd ~/Git/TOSEM_Formal_Guided_Vibe_Coding && git push
```

```bash
cd ~/Gitee/formal_method_guided_vibe_coding && git push origin condition-f
```

## 1. Each session

Start (replace the three arguments with the row of the table below):

```bash
bash ~/Gitee/formal_method_guided_vibe_coding/scripts/v3_start.sh cold sranger 1
```

Setup must end with READY; if it prints FAIL, send the output and do not start the
session. The prompt is then on the clipboard. In a new Claude Code session in the
worktree the script opens: type `/model`, confirm Claude Opus 5.5, and paste the
text (Cmd+V; do not attach the file).

A cold pass stops by itself after one pipeline run. A Reference run iterates by
itself until it converges or reaches iteration 7. When the session stops, type
`/export transcript.md` in it, then run the three checks below and paste their
output (replace the worktree name: `forge-v3c-run<k>-<study>` for cold,
`forge-v3r-run<k>-<study>` for Reference):

```bash
python3 ~/Gitee/formal_method_guided_vibe_coding/scripts/session_commands.py forge-v3c-run1-sranger > /tmp/v3-cmds.txt
```

```bash
python3 ~/Gitee/formal_method_guided_vibe_coding/scripts/session_hooks_skills.py forge-v3c-run1-sranger > /tmp/v3-hooks.txt; wc -l /tmp/v3-hooks.txt
```

```bash
bash -c 'shopt -s nullglob; d=$(ls -d ~/.claude/projects/*forge-v3c-run1-sranger); echo "models: $(grep -ho "\"model\":\"[^\"]*\"" $d/*.jsonl | sort | uniq -c | tr "\n" " ")"; echo "versions: $(grep -ho "\"version\":\"[^\"]*\"" $d/*.jsonl | sort | uniq -c | tr "\n" " ")"'
```

I audit the transcript and the logs, write `TRANSCRIPT_AUDIT.md` into the run
directory and send the finish command, for example:

```bash
bash ~/Gitee/formal_method_guided_vibe_coding/scripts/v3_finish.sh cold sranger 1 "converged"
```

`v3_start.sh` refuses number k of a study until k-1 of the same collection is
committed, so the collections stay in order.

## 3. A void pass or run

I write the reason into the run directory as `VOID.md`, you commit it with the
finish command, and the study gets a replacement numbered 11, 12, … (cold) or 6, 7, …
(Reference), run after row 46. Replacement prompts are generated by the same script
and committed before they are used.

## 4. Scoring

Each committed pass and run is scored by me from its own records at the pin; no
separate replay is needed, because the pin is the published pipeline. After row 46
I rebuild Tables 5–7, rewrite Sections 4.5–4.6 and 4.10 and update the letter.
