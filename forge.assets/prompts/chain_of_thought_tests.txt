STEP-BY-STEP REASONING FOR TEST GENERATION

Step 1: Test structure.
- Use JUnit Jupiter 5 with @Nested test classes for organization
- Each test class covers one package or major component
- Use @BeforeEach for setup, static DELTA = 1e-9 for double comparisons

Step 2: Identify testable components from the generated source code.
- For each Java class in the source code, create a corresponding test class
- Focus on public methods and their expected behaviour based on the requirements
- Ensure each requirement has at least one test covering it

Step 3: Test design principles.
- Use known values (e.g., Pythagorean triples for distance tests)
- Test both positive and negative cases (guard satisfied vs not satisfied)
- Test boundary conditions (e.g., threshold values, empty collections)
- Use helper methods to set up common state for transition tests

Step 4: Traceability.
- Name test methods clearly to indicate which requirement they cover
- Group related tests in @Nested classes
- Use comments to reference requirement IDs where helpful

Step 5: Demo application.
- Create an entry-point class that demonstrates the full system lifecycle
- Walk through a realistic scenario showing key transitions and state changes
- Print state at each step for visibility

Step 6: Output all test files and the demo application as a JSON manifest.
